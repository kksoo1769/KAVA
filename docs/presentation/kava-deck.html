  • 원본 Linear 객체를 보관했다가 되돌려 끼우도록 직접 구현
  • 가중치를 복사하지 않아 요청마다 전환 가능

PyTorch 경로에서는 시각 토큰 784개의 prefill 활성값이 약 6.3GB를 차지합니다.

텍스트 질문용 언어 모델을 따로 올릴 메모리 여유는 없었습니다. 그래서 언어 모델을 한 벌만 올려두고 LoRA 어댑터를 켜면 이미지용, 끄면 텍스트용으로 사용했습니다. 그런데 기존 라이브러리에 어댑터를 끄는 기능이 없었습니다. 따라서 원본 Linear 객체를 들고 있다가 되돌려 끼우는 스위치를 구현하였습니다.

스트리밍 계약

progressdeltadoneerror

  • 완료는 정확히 한 번, 항상 마지막
  • 시작 후 오류는 상태 코드 대신 이벤트로
  • 최종 답변은 조각의 합이 아니라 그래프 상태에서 추출 조각이 유실돼도 턴이 끝나면 화면이 스스로 교정
  • 진행 알림에는 사람이 읽을 한 줄만. 내부 상태는 비노출

스트리밍에서 실제로 겪은 문제

반쪽 태그 노출태그로 이어질 수 있는 꼬리 길이만큼 보류. 앞 공백도 함께
사고 과정 노출종료 태그까지 전량 보류
도구 호출 JSON 파손실패를 세어 두고 전부 실패면 재시도 문구를 본문에 부착
추론만 하다 예산 소진서버가 종료 사유를 함께 반환, 어댑터가 안내 문구로 번역

세션과 동시성

  • 확정 상태를 깊은 복사해 작업, 정상 종료 시에만 커밋
  • 처리 중 세션의 재요청은 대기 없이 409 줄 세우면 같은 질문이 두 번 실행됨
  • 동일 request_id는 잠금 이전에 캐시로 응답
  • 추론 서버는 단일 워커와 큐. 종료 신호는 finally로 보장

자체 서버를 LangGraph 도구 호출 루프에 연결

OpenAI 호환이 아닌 자체 스키마, 도구 호출은 본문 태그. BaseChatModel 어댑터로 스키마와 호출 id, 스트리밍 형식을 맞췄습니다. 조각은 문자열이 아니라 청크 객체끼리 더합니다. 문자열로 합치면 도구 호출이 조용히 사라집니다.

교체 가능한 백엔드

추론 백엔드를 환경변수로 교체합니다. 지연 import로 의존성을 분리해 MLX로 돌 때 PyTorch 계열 377MB가 서버 프로세스에 상주하지 않습니다.

마지막은 서빙입니다. SSE는 첫 바이트가 나간 다음에는 상태 코드를 못 바꿀 수 없습니다. 그래서 계약부터 고정했습니다. 이벤트를 네 종류로 두고, 완료는 정확히 한 번만, 항상 마지막에 나가게 했습니다. 최종 답변은 조각을 이어 붙인 게 아니라 그래프 상태에서 따로 꺼내서, 조각이 유실되거나 도구 호출 태그가 새어 나가도 턴이 끝나면 화면이 스스로 교정되게 하였습니다. 실제로 태그가 반쪽만 화면에 보이는 문제가 있었는데, 다음 청크에서 태그로 이어질 수 있는 부분만큼 보류해 해결할 수 있었습니다. 세션은 트랜잭션처럼 다뤘습니다. 깊은 복사로 작업하고 정상 종료했을 때만 커밋하고, 전송을 두 번 누르면 기다리지 않고 409 상태 코드로 거절하게 하였습니다. 추론 백엔드는 환경변수로 갈아끼우는데, MLX로 돌 때 PyTorch의 메모리 사용이 아예 없게 분리하였습니다.
